## Owner decision (already made, don't re-litigate)
The game is only played in landscape. From v1.4.0 it is **landscape-only on phones and tablets**. This overrides the CLAUDE.md
product rule "Portrait iPhone is the main target". Goal: a reliable landscape experience and one arena shape family,
so a later version can add a scrolling camera. Keep this change small and reversible.

## Changes (keep the scope to exactly these)
1. **Arena is always landscape.** `gridForAspect()` in `src/arena.js` must never return a portrait grid (rows > cols):
   clamp the aspect it uses to ≥ 4/3. Landscape results stay exactly as today (16:9 → 32x18, iPad landscape → 28x20),
   so existing landscape layouts don't change. Do NOT delete the portrait code paths (`PORTRAIT`, `setOrientation`,
   `body.portrait` CSS, portrait tests); they just stop being used. Removing them is a later cleanup.
2. **"Rotate your device" overlay.** On a touch device held in portrait (`isPortraitScreen()` in src/main.js), show a full-screen
   overlay over everything: a rotate icon, "Overdue! plays in landscape", "Turn your phone sideways". Use a new
   `<section>`/element in index.html and CSS in src/game.css with tokens scoped to that component (not `:root`).
   - It appears and disappears live on rotation (the `resize` listener).
   - If a run is in progress (`game.state === 'playing'`), rotating to portrait calls `pause()`; rotating back shows the
     normal pause screen (no auto-resume, so the player isn't hit while turning the phone).
   - Desktop/non-touch browsers never show it, even in a narrow window: there they just letterbox the landscape arena.
   - On rotation to landscape while on the title/game-over screen, `applyLayout()` must re-shape the arena as it already does.
3. **Manifest:** `manifest.webmanifest` `"orientation": "landscape"`. Fullscreen orientation lock (around line 2142 of
   src/main.js, `screen.orientation.lock(...)`): always lock to `'landscape'`.
4. **Docs:** CLAUDE.md product rule → "Phone first, **landscape only** (since v1.4.0): iPhone landscape is the main target;
   iPad and desktop must also fill the screen. In portrait, touch devices show a rotate overlay." Update README.md
   (mention landscape-only and the rotate screen) and TESTING.md (device list). Mark v1.4.0 done in ROADMAP.md's plan table.
