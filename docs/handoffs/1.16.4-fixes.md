## 2. Permanent blue circle (owner)
Owner: "There is a permanent blue circle that looks like a control that didn't work. The default aiming should be auto-aim."
The circle is the manual aim stick (`drawAimStick`, drawn while `touch.aimId !== null`, main.js ~2467/2855). Auto-aim is already the
default (`settings.autoaim !== false`), so the likely cause is a **stuck second touch**: an aim touch that never got its touchend
(touchcancel, an iOS edge/system gesture, a finger lifted while paused / on a menu / during a screen change), so aimId stays set, the
circle stays, and (per "deflected stick: throws follow the stick") it can even override auto-aim.
Fix: clear aim (and move) touches on touchcancel, on blur/visibilitychange, on pause and whenever an overlay/menu opens or a room starts;
if the touch id is no longer in `e.touches` on any touch event, drop it. With auto-aim on, don't draw the aim stick until the second
finger has actually dragged past the deadzone; a resting finger shows nothing and doesn't override auto-aim. Manual aim (auto-aim off)
keeps today's behaviour. Make sure the default for a fresh install and for old saves without the key is auto-aim ON.
QA: (a) start an aim touch, fire touchcancel (and separately: pause mid-touch, resume) → no aim stick drawn, auto-aim fires;
(b) a resting second finger inside the deadzone with auto-aim on → no circle, auto-aim keeps working; (c) fresh install → auto-aim on.
