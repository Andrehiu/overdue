## Problem (owner playtest on iPad + measured by the planner; don't re-investigate)
In landscape (the game is landscape-only since v1.4.0) menus overflow the screen and their **Back button ends up below the
bottom edge**. Menus are `section.screen` (src/game.css: `overflow-y: auto`, content centred with `margin: auto` on the first
and last child), so the Back button is only reachable by scrolling, which players don't notice. Measured (Playwright,
overflow = content taller than screen, "cut" = how far the last button sits below the screen):

| Screen | iPhone SE land. 568x320 | iPhone 13 land. 750x342 | iPhone 15 Pro Max 814x380 | iPad mini 1133x744 | iPad 1180x740 (Safari bars) | Desktop 1280x720 |
|---|---|---|---|---|---|---|
| Codex | Back cut 283px | cut 298px | cut 329px | cut 513px | cut 517px | cut 537px |
| Renovations (shop) | cut 1px | cut 10px | overflow 13px | ok | ok | overflow 17px |
| Settings | cut 4px | overflow 6px | ok | ok | ok | ok |
| Title | overflow 13px | overflow 11px | overflow 7px | overflow 60px | overflow 64px | ok |
The owner's own iPad screenshot of Renovations also showed Back cut off, and the iPad status bar (clock) drawn over the top-right.
The game-over screen already solved this with a sticky button row (`#gameover .menu.row { position: sticky; bottom: 0; ... }`).
