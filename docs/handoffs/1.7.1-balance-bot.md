## Branch

## Why
The owner will tune door and wing balance after playing. A bot that plays many runs gives relative numbers to start from
("always Rare Books dies in room 3 of wing 7 most of the time"). It does not replace human testing: a bot plays worse than people,
so only compare policies and wings with each other, never read absolute difficulty from it.

## What to build
1. `scripts/balance.mjs` + npm script `npm run balance` (NOT part of `npm run qa` or CI). Uses Playwright (already a dev dependency)
   against the local static server, like scripts/qa/run.mjs, with `?debug=1`. Add any debug hooks it needs to `window.__overdue`
   in src/main.js (debug-only; no gameplay change), e.g. reading player/enemy positions, choosing a door or a perk card by index.
2. **Bot** (runs inside the page each frame or on a short interval): move away from the weighted centre of nearby threats (enemies
   and enemy pages) while staying out of corners; auto-aim/auto-fire as on touch; dash when an enemy page or enemy is about to hit;
   SHHH when 4+ enemies are close. Perk pick: a fixed priority list (damage, throw rate, hearts first), Banish/Renew unused.
3. **Policies for doors:** `rare` (always Rare Books when offered), `rest` (Break Room / Stacks when offered), `mixed` (Break Room
   when at ≤ 2 hearts, else Rare Books, else first door). Mystery Shelf only when it's the only non-fixed option left by the policy.
4. **Runs:** wings 1, 4, 7, 10 × 3 policies × N runs (default N = 20, `--runs=N` and `--wings=1,4` flags), speed up the game
   clock if a debug time-scale exists or can be added safely (debug-only); fresh progress each run (no Renovations), and also a
   second pass with a mid-game save (all Renovations at about half level) via `--renos=half`.
5. **Report** `balance-report/report.md` (gitignored folder): per wing × policy: clear rate, death-room distribution (rooms 1–10),
   average hearts left when clearing, average fines earned, average run time; plus a short "what stands out" list computed from the
   numbers (e.g. biggest drop in clear rate between adjacent wings, policy with the best fines per run). Also `report.json`.
6. Keep it robust: a run that hangs > 3 minutes of game time is recorded as "timeout"; the script never fails the whole batch on one run.
